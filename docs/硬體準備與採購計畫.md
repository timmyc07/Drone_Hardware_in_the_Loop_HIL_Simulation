# 無人機 HIL 研究硬體準備與採購計畫

> **版本日期：2026-10-26**
> 本計畫以「自製 STM32 控制器 + 第二片 STM32 PWM 擷取板 + PC 植物模型」為主線。初期只做無槳、低能量 bench 測試；不先購買 ESC、馬達或螺旋槳。

## 1. 硬體準備目標

先建立可量測、可重播的最小硬體迴路：PC 傳送虛擬感測值，STM32 執行控制並輸出實體 PWM，第二片 STM32 以 timer input capture 量測 PWM，再回傳資料供 PC 更新植物模型。Unity 只作後續視覺化，不是前期硬體驗收的前置條件。

本硬體配置驗證控制程式、UART、PWM 輸出及擷取鏈路；不會驗證實體 IMU 的 SPI/I²C driver，也不代表 ESC/馬達推力模型已校準。

## 2. 建議系統接線

```text
PC / HIL Host
  ├── USB data cable ── Controller NUCLEO (virtual sensor UART → control → PWM)
  ├── USB data cable ── Capture NUCLEO (timer input capture → capture telemetry)
  └── Logic analyzer ── PWM[0..3] + UART TX/RX + timing marker

Controller PWM outputs ──> Capture NUCLEO timer inputs
Controller GND ─────────── Capture NUCLEO GND
```

兩片板分工不同：controller board 執行受測控制器，capture board 量測實際腳位波形。初期以 USB 為兩片板各自供電；連接 PWM 訊號時接共地，不要把兩板的 5 V rail 互相短接或回灌。

## 3. 核心必備硬體清單

| 品項 | 數量 | 最低採購/使用條件 | 用途 | 採購時點 |
|---|---:|---|---|---|
| STM32 NUCLEO-G474RE 或同等 STM32G4 Nucleo | 2 片 | 同型號優先；controller 與 capture board 各一片。若已有可用 STM32 開發板，先確認 timer、UART、I/O 腳位與工具鏈再決定是否購買 | 控制器、四路 PWM 輸出、timer capture | 第 1 階段 |
| USB 資料線 | 2 條 | 必須可傳資料，接頭依實際板卡 revision；不要買僅供電線 | ST-LINK/VCP、燒錄、USB 供電 | 第 1 階段 |
| 8 通道數位邏輯分析儀 | 1 台 | 可同時擷取至少 8 路；建議每通道取樣率至少 10 MS/s；輸入門檻需支援 3.3 V 邏輯。量測前查明 sample clock 精度與每通道/總取樣率標示 | 同步觀察四路 PWM、UART TX/RX、GPIO timing marker，並交叉核對 timer capture | 第 1 階段 |
| 數位萬用電表 | 1 台 | 可量 DC 電壓、導通與短路；先確認表筆及保險絲狀態 | 核對 3.3 V、5 V、共地、短路與供電接線 | 第 1 階段 |
| 杜邦線、排針、無焊麵包板或固定板 | 1 組 | 至少能穩固連接 PWM、GND、UART 測試點；訊號線盡量短且標籤化 | bench 接線及 pin mapping | 第 1 階段 |
| 開發用 PC | 1 台 | 使用現有電腦即可；需能執行 STM32CubeIDE、HIL Host、資料記錄與後續 Unity viewer | 燒錄、通訊、植物模型、記錄與分析 | 先盤點現有設備 |

NUCLEO-G474RE 目前由 ST 列為 Active/量產中，且板載 ST-LINK；UM2505 說明 VCP 使用哪個 USART/LPUART 及焊橋選擇。採購時須依收到的板卡 revision 核對 USB 接頭、焊橋預設和 pinout，不要直接照網路舊版接線圖。[H01–H02]

8 通道是因四路 PWM、兩條 UART 線和至少一條 timing marker 共需七路同步觀察，保留一個備用通道。10 MS/s 的 sample interval 為 0.1 µs；這是取樣間隔，不等於儀器的絕對時間精度，實際誤差還受 sample clock 精度影響。[H04]

## 4. 分階段準備與驗收

### Stage 0：盤點，不急著採購

先清點實驗室現有 MCU 板、USB 線、邏輯分析儀、示波器、萬用電表與電源。記下板卡完整型號/revision、可用 timer channel、VCP UART 路由、I/O 電壓與電腦作業系統。若已有兩片合用 STM32 板，可直接先做 bench，不必為了型號一致重複買設備。

**輸出：** 設備盤點表、板卡版本照片、初步 pin map、缺料清單。

### Stage 1：PWM 輸出/擷取 bench

1. Controller board 先輸出一路固定 PWM，接至 capture board 的 timer input pin。
2. Capture board 以硬體 timer capture 取得上升沿/下降沿；以高低沿差計脈寬，以相鄰上升沿差計週期。
3. 逐步擴成四路 PWM，記錄各 channel 的脈寬、週期、計時器 tick、漏脈衝與計數器 wrap handling。
4. 邏輯分析儀同時觀察 PWM 和 timing marker，與 capture board 記錄交叉核對。
5. 先測易讀取的低頻 PWM，再依未來目標輸出協定掃描頻率；測試頻率需記錄，不把控制迴圈頻率當成 PWM frame rate。

**通過條件：** 能連續擷取四路輸出並保存原始資料；量測差異及儀器時間精度有記錄；拔線或停止輸出時可識別逾時/漏脈衝。STM32 timer input capture 的官方說明可作設定依據。[H03]

### Stage 2：UART 與最小 HIL 數位閉環

1. 兩片板各自透過 USB VCP 連到 PC；確認作業系統可辨識兩個獨立 serial port。
2. PC 傳送 MAVLink `HIL_SENSOR`，controller board 驗證解析出的時間戳、序號、SI 單位和更新旗標。
3. Controller board 輸出 PWM，capture board 建議以自訂 MAVLink dialect 訊息 `PWM_CAPTURE` 回報量測值；先量 UART 吞吐、CRC/序號錯誤、timeout 和資料齡期。
4. 先以 100 Hz 功能基線運行，再測 250 Hz；各自記錄 host 更新頻率、MCU loop rate 和 PWM frame rate。
5. 斷開 USB 或停止 sensor frame，確認控制端進入定義好的安全輸出，Host 停止使用過期資料並保存故障紀錄。

**通過條件：** 可連續運行至少 10 分鐘並保存完整 raw log；報告封包錯誤、timeout、deadline miss、p50/p95/p99/max latency。通過基線後才決定是否提升頻率，不以尚未量測的 1–2 ms 作採購驗收門檻。[H05]

### Stage 3：模型參數校準設備（選配）

只有當論文要主張 PWM→轉速/推力/力矩模型有物理校準時，才添購此階段設備。使用 PWM 輸出值直接推力是未校準假設，不能取代實測。

| 品項 | 數量 | 選型前需確認 | 用途 |
|---|---:|---|---|
| 推力測試架及 load cell/推力計 | 1 組 | 依選定馬達與槳的預期最大推力選量程及過載能力；不得先猜固定量程 | 量測 PWM/轉速到推力的映射 |
| ESC、馬達、螺旋槳 | 1 組 | 後續研究範圍確認後，依電壓/電流、KV、槳尺寸、推力架能力配套 | 馬達 lag、deadband、推力與電流實驗 |
| 轉速計/光學 tachometer | 1 台 | 量程覆蓋所選馬達預期 RPM；與反光標記/感測配置相容 | 取得 RPM 供推力模型識別 |
| 電壓/電流量測與限流電源 | 各 1 | 額定電壓、連續/峰值電流需覆蓋馬達和 ESC；初次試驗須有限流及急停 | 量測輸入功率、電池壓降、電流保護 |
| 槳葉防護罩、剛性固定架、急停/斷電開關 | 各 1 | 與測試架幾何和最大推力相容；依實驗室安全程序審核 | 降低旋轉槳與失控輸出風險 |

**購買閘門：** 先有指導教授/實驗室同意、完成風險評估和無槳 HIL，再選馬達與推力架。未完成防護、固定、急停和供電檢查，不進行帶槳測試。

### Stage 4：真實感測器噪聲校準設備（選配）

| 品項 | 數量 | 選型條件 | 用途 |
|---|---:|---|---|
| IMU breakout board | 1–2 | 優先與預計驗證的 IMU 型號/量程/取樣率相同；確認資料手冊與介面 | 靜置記錄 gyro/accel noise、bias 和溫度影響 |
| 穩固、低振動桌面與固定夾具 | 1 組 | 可保持感測器靜止，避免桌面振動及線材拉扯 | Allan deviation 和靜態噪聲量測 |
| 溫度記錄器（選配） | 1 | 可同步記錄測試環境溫度 | 分析 bias 隨溫度變化；非第一階段必備 |

如果只做合成噪聲壓力測試，不需要買 IMU breakout；如果要聲稱噪聲參數代表實際 sensor，須使用對應型號並保存長時間靜態資料和環境條件。

## 5. 不建議第一階段購買

- ESC、無刷馬達、螺旋槳、飛行機架和電池：不需要完成 controller/PWM HIL；帶槳測試增加風險。
- 推力架、load cell 和 tachometer：只有做致動器/推力物理校準才需要，先完成需求與量程計算。
- 高階示波器、商用 real-time target、額外 USB-UART 轉接器：先確認邏輯分析儀、VCP 和現有 PC 能否完成基線；有訊號完整性、排程或 VCP 問題再添購。
- GNSS、相機、氣壓艙、磁場線圈：不在第一版姿態 HIL 範圍。

## 6. 安全及接線檢查

- 初期全程無槳，板卡只由 USB 供電；不要將兩板 5 V rail 並接。
- 只連經 pinout 確認的 3.3 V PWM/GND；電壓容忍度逐 pin 依 datasheet/board manual 核對，不因某些腳位 5 V tolerant 就推定全板相同。
- 萬用電表先量供電、共地與短路；首次上電限流，先單路 PWM，再擴四路。
- 線材標示 controller/capture、PWM channel、UART TX/RX/GND；每次更改焊橋或接線更新 pin map。
- 帶槳推力測試須使用固定台、槳葉護罩、遠端急停和實驗室核准的程序；它不是核心 HIL bring-up 的必要步驟。

## 7. 採購與工作節奏

| 週次 | 採購/準備 | 可進入下一步的證據 |
|---|---|---|
| 第 1 週 | 盤點現有設備；只補 controller/capture 兩片相容板、USB 資料線、接線材料和量測器材 | USB/VCP 連線、板 revision/pin map 確認 |
| 第 2 週 | 完成單路到四路 PWM output/capture 與邏輯分析儀比對 | 四路 pulse/period log，辨識漏脈衝和 timer wrap |
| 第 3 週 | PC Host 對 controller 注入 `HIL_SENSOR`，capture board 回傳 `PWM_CAPTURE` | 100 Hz 連續傳輸，CRC/timeout/資料齡期 log |
| 第 4 週 | 單軸植物模型閉環、斷線故障測試 | 可重播的 10 分鐘閉環資料及 failsafe 記錄 |
| 通過第 4 週後 | 擴展 6-DOF/Unity；依論文主張決定是否添購 IMU 或推力台設備 | 明確說明要校準的參數、量程及所需校準資料 |
