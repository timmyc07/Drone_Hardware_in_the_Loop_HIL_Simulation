# 機載相機資料

先前單機版本曾完成 GPU 測試及三影格資料集往返；多機版本的瀏覽器驗證仍在進行。相機資料為模擬場景影像，不代表真實相機、經校準的感測器或物件偵測 AI；沒有熱成像或紅外線感測。飛行物理使用模型 0.9.0，現行飛行紀錄為 schema 12；相機資料集是獨立 JSON，不會包含在飛行紀錄或其重播中。

## 三種同步輸出

同一次拍攝取得相同姿態與模擬時間的 RGB、平面深度及分類影像。深度 `depthM` 以公尺表示相機光軸 Z 方向距離，0 表示無效或無回波；它不是從相機出發的徑向距離。分類值為場景語意類別，並非物件實例識別：

| ID  | 類別       |
| --- | ---------- |
| 0   | 天空       |
| 1   | 地面       |
| 2   | 跑道       |
| 3   | 植被       |
| 4   | 結構物     |
| 5   | 障礙物     |
| 6   | 訓練門     |
| 7   | 其他飛行器 |

拍攝可按需觸發或使用最高 2 Hz 即時預覽；拍攝機自身不出現在影像中，其他載具可出現在 RGB、深度及分類圖。`worldTick` 在內建世界為共同 200 Hz 物理步數，本機外部飛控為其植物模型的物理步數。相機以物理質心為原點；內參設定僅含 `width`、`height`、`horizontalFovDeg`、`nearM`、`farM`，方向由三軸雲台實際姿態提供，見[雲台說明](雲台說明.md)。預設 320 × 240、水平視場角 90°、近／遠裁切 0.1／200 m。各影格包含 `sourceVehicleId`、`worldTick`、實際姿態、內參、地理來源（無地理場景時為 null）與 RGB、深度、分類陣列；過往版本 2 三影格資料集瀏覽器往返曾驗證。

## 坐標與內參

世界座標使用 NED（北、東、下），機體使用 FRD（前、右、下）；相機光學座標採 x 向右、y 向下、z 向前。這與 [ROS REP-103 光學座標約定](https://github.com/ros-infrastructure/rep/blob/master/rep-0103.rst)一致，但不代表具備 ROS 介接。針孔模型以焦距 `fx`、`fy` 和主點 `cx`、`cy`（單位像素）描述投影，參考 [ROS CameraInfo](https://github.com/ros2/common_interfaces/blob/rolling/sensor_msgs/msg/CameraInfo.msg)。影像尺寸為 W × H，水平視場角為 h 時，方形像素假設下 `fx = W / (2 tan(h/2))`、`fy = fx`；主點為 `cx=(W-1)/2`、`cy=(H-1)/2`，像素由左上角開始逐列排列。`pose.opticalToNed` 為列優先 3×3 矩陣，將光學坐標方向轉為 NED；`positionNed` 位於機體質心，沒有安裝平移偏移。深度在渲染時四捨五入至毫米，儲存為 Float32。

Three.js `PerspectiveCamera` 使用垂直視場角，與介面的水平視場角不同，需按寬高比轉換。專案使用 Three.js 0.187.0；Context7 僅索引至 r186，已核對 [r187 官方原始碼](https://github.com/mrdoob/three.js/blob/r187/src/cameras/PerspectiveCamera.js) 的視場角定義。平面深度與分類概念另參考 [AirSim 影像 API](https://github.com/microsoft/AirSim/blob/main/docs/image_apis.md)，不表示本專案採用 AirSim。

## 資料集、限制與錯誤

獨立相機資料集上限為 30 個影格或約 24 MiB 原始影像資料；JSON 體積可能更大。達到上限或渲染、匯出失敗時操作會回報錯誤。UI 支援單張擷取、RGB PNG 匯出及獨立資料集 JSON 匯入、匯出與檢視。即時預覽的 2 Hz 為牆上時間上限，不是硬即時保證；已確認預覽會更新影格，尚未驗證長時間擷取效能。暫停時仍可依目前姿態拍攝；重播會停用新拍攝，既有相機資料集仍可選取及匯出。瀏覽器圖形支援、記憶體和背景分頁節流可能影響擷取。不要將深度預覽的顯示亮度當作原始公尺資料。

資料集頂層 `format` 為 `flight-lab-camera-dataset`、`version` 為 4，包含 `encoding`、`classes` 圖例與 `frames`；影格的 `rgbRgba`、`depthM`、`classes` 分別以 `base64-rgba8`、`base64-float32-le-meters`、`base64-uint8` 編碼。版本 1–3 不相容；匯入上限 40 MiB，解析時檢查欄位、圖例、緩衝長度、深度及分類範圍；內參與姿態矩陣允許 1e-12 浮點容差以容納不同引擎的三角函數差異，設定欄位嚴格核對。

資料集可跨模擬重設保留，時間戳可能倒退或來自不同時段；請以影格排列順序辨識，不能假設與某份飛行紀錄逐影格對應。API `captureCamera(vehicleId)` 只回傳複製的當前影格，不自動加入資料集；UI「拍攝並加入資料集」才加入。無鏡頭畸變、曝光、實體相機校準、熱成像或視覺控制器模型。

先前單機版本初步 GPU 測試中，四旋翼於約 2 m 向下拍攝，76,800 個深度均有效且約為 2 m；地面與跑道各 38,400 像素。切換主視角至 FPV 並關閉畫面渲染後，相同姿態的 RGB、深度與分類輸出逐位元組相同；這是特定場景測試，不代表實機精度。

先前單機版本瀏覽器實測三張影格匯出、匯入、選取後再次匯出，其中繼資料和原始緩衝區完全一致，並核對 320 × 240 PNG。向下拍攝時偏航 0° 的跑道位於畫面上半部，偏航 +90° 時位於左半部；此證據限於該測試場景。
