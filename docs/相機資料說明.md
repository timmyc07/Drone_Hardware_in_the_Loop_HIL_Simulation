# 機載相機資料

先前單機版本曾完成 GPU 測試及三影格資料集往返；0.20 多機瀏覽器驗證已完成。相機資料為模擬場景影像，不代表真實相機、經校準的感測器或物件偵測 AI；沒有熱成像或紅外線感測。飛行物理使用模型 0.11.0，現行飛行紀錄為 schema 15；相機資料集是獨立 JSON，不會包含在飛行紀錄或其重播中。

## 三種同步輸出

同一次拍攝取得相同姿態與模擬時間的 RGB、平面深度及分類影像。深度 `depthM` 以公尺表示相機光軸 Z 方向距離，0 表示無效或無回波；它不是從相機出發的徑向距離。分類值為場景語意類別，並非物件實例識別：

| ID  | 類別       |
| --- | ---------- |
| 0   | 天空       |
| 1   | 地面       |
| 2   | 跑道       |
| 3   | 植被       |
| 4   | 結構物     |
| 5   | 障礙物     |
| 6   | 訓練門     |
| 7   | 其他飛行器 |

拍攝可按需觸發或使用最高 2 Hz 即時預覽；拍攝機自身不出現在影像中，其他載具可出現在 RGB、深度及分類圖。`worldTick` 在內建世界為共同 200 Hz 物理步數，本機外部飛控為其植物模型的物理步數。相機以物理質心為原點；內參設定僅含 `width`、`height`、`horizontalFovDeg`、`nearM`、`farM`，方向由三軸雲台實際姿態提供，見[雲台說明](雲台說明.md)。預設 320 × 240、水平視場角 90°、近／遠裁切 0.1／200 m。各影格包含 UUID `captureId`、`sourceVehicleId`、`worldTick`、實際姿態、內參、地理來源（無地理場景時為 null）與 RGB、深度、分類陣列；過往版本 2 三影格資料集瀏覽器往返曾驗證。

## 自動拍攝（0.26）

「感測器」的機載相機可對目前選中的內建模擬載具啟動自動拍攝，沿用目前雲台方向，不會自動起飛或修改雲台。僅在模擬運行且離地高度至少 0.5 m 時開始新拍攝；暫停或背景分頁時等待。重播及外部原生 SITL 不支援啟動。

可選模擬時間間隔 0.5–300 秒，或接收快照的水平累積路徑間隔 0.25–500 m。牆上時間最多每秒兩張，同時最多一張等待完成；不補拍或插值，實際間隔可能增加。每次最多新增 1–30 張，整頁資料集共用 30 張或 24 MiB 上限，先達上限即停止拍攝並保留資料，飛行不會因此自停。停止、重設、進入重播或切換載具會取消尚未完成影像的追加；清除與匯入期間會鎖定資料集操作。

這不是 Worker 物理事件，也不保證相片重疊率、測繪覆蓋或避障。飛行紀錄 schema 15 與相機資料集版本 5 不變，模型升至 0.11.0；影像須獨立匯出。參考 [QGroundControl 相機控制](https://github.com/mavlink/qgroundcontrol/blob/36436db319c731b70ab25dd3178896c4c22c75f6/src/MissionManager/CameraSection.cc)及[測繪網格](https://github.com/mavlink/qgroundcontrol/blob/36436db319c731b70ab25dd3178896c4c22c75f6/docs/en/qgc-user-guide/plan_view/pattern_survey.md)的行為，未複製程式碼。0.26 的實際拍攝、容量及資料集往返驗證見 [automatic-camera-v026.json](validation/automatic-camera-v026.json)。

## 測繪相機規劃（0.27）

[測繪網格](測繪網格任務.md)可依目前相機內參、固定平面高度及前／側重疊率估算足跡、地面解析度、線距與距離拍攝間距。黃色矩形僅表示首航點的理想第一張足跡。套用會設定正下視雲台、距離自動拍攝控制及普通航點草稿，不會飛行或啟動拍攝；須另行開始任務及自動拍攝。

拍攝可能涵蓋進場及連接航段，任務完成不會自動停拍，請手動停止。套用時拍攝張數上限設為資料集剩餘可容納數；既有 2 Hz、30 張及 24 MiB 限制仍適用。固定平面估算不提供地形自適應、實際重疊保證、拼接、正射影像或實機校準。版本及介面格式保持不變，驗證摘要見 [survey-camera-v027.json](validation/survey-camera-v027.json)。

## 坐標與內參

世界座標使用 NED（北、東、下），機體使用 FRD（前、右、下）；相機光學座標採 x 向右、y 向下、z 向前。這與 [ROS REP-103 光學座標約定](https://github.com/ros-infrastructure/rep/blob/master/rep-0103.rst)一致，但不代表具備 ROS 介接。針孔模型以焦距 `fx`、`fy` 和主點 `cx`、`cy`（單位像素）描述投影，參考 [ROS CameraInfo](https://github.com/ros2/common_interfaces/blob/rolling/sensor_msgs/msg/CameraInfo.msg)。影像尺寸為 W × H，水平視場角為 h 時，方形像素假設下 `fx = W / (2 tan(h/2))`、`fy = fx`；主點為 `cx=(W-1)/2`、`cy=(H-1)/2`，像素由左上角開始逐列排列。`pose.opticalToNed` 為列優先 3×3 矩陣，將光學坐標方向轉為 NED；`positionNed` 位於機體質心，沒有安裝平移偏移。深度在渲染時四捨五入至毫米，儲存為 Float32。

Three.js `PerspectiveCamera` 使用垂直視場角，與介面的水平視場角不同，需按寬高比轉換。專案使用 Three.js 0.187.0；Context7 僅索引至 r186，已核對 [r187 官方原始碼](https://github.com/mrdoob/three.js/blob/r187/src/cameras/PerspectiveCamera.js) 的視場角定義。平面深度與分類概念另參考 [AirSim 影像 API](https://github.com/microsoft/AirSim/blob/main/docs/image_apis.md)，不表示本專案採用 AirSim。

## 資料集、限制與錯誤

獨立相機資料集上限為 30 個影格或約 24 MiB 原始影像資料；JSON 體積可能更大。達到上限或渲染、匯出失敗時操作會回報錯誤。UI 支援單張擷取、RGB PNG 匯出及獨立資料集 JSON 匯入、匯出與檢視。即時預覽的 2 Hz 為牆上時間上限，不是硬即時保證；已確認預覽會更新影格，尚未驗證長時間擷取效能。暫停時仍可依目前姿態拍攝；重播會停用新拍攝，既有相機資料集仍可選取及匯出。瀏覽器圖形支援、記憶體和背景分頁節流可能影響擷取。不要將深度預覽的顯示亮度當作原始公尺資料。

資料集頂層 `format` 為 `flight-lab-camera-dataset`、`version` 為 5，包含 `encoding`、`classes` 圖例與 `frames`；影格的 `rgbRgba`、`depthM`、`classes` 分別以 `base64-rgba8`、`base64-float32-le-meters`、`base64-uint8` 編碼。版本 1–4 不相容；匯入上限 40 MiB，解析時檢查欄位、圖例、緩衝長度、深度及分類範圍；內參與姿態矩陣允許 1e-12 浮點容差以容納不同引擎的三角函數差異，設定欄位嚴格核對。

資料集可跨模擬重設保留，時間戳可能倒退或來自不同時段；請以影格排列順序辨識，不能假設與某份飛行紀錄逐影格對應。API `captureCamera(vehicleId)` 只回傳複製的當前影格，不自動加入資料集；UI「拍攝並加入資料集」及自動拍攝會加入。無鏡頭畸變、曝光、實體相機校準、熱成像或視覺控制器模型。

先前單機版本初步 GPU 測試中，四旋翼於約 2 m 向下拍攝，76,800 個深度均有效且約為 2 m；地面與跑道各 38,400 像素。切換主視角至 FPV 並關閉畫面渲染後，相同姿態的 RGB、深度與分類輸出逐位元組相同；這是特定場景測試，不代表實機精度。

先前單機版本瀏覽器實測三張影格匯出、匯入、選取後再次匯出，其中繼資料和原始緩衝區完全一致，並核對 320 × 240 PNG。向下拍攝時偏航 0° 的跑道位於畫面上半部，偏航 +90° 時位於左半部；此證據限於該測試場景。

巡檢影格的雜湊與報告配對方式見[設施巡檢](設施巡檢.md)；相機資料集須與飛行紀錄分開保存。
