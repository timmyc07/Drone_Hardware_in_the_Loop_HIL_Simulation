# 共用世界多機模擬（0.20）

在飛行畫面上方展開「管理機隊」，可設定 1–8 架四旋翼、固定翼、VTOL、六旋翼或八旋翼。每架都有穩定且唯一的 ID、名稱、模型設定、起點、航向與家點；套用會重設全隊及目前暫存紀錄，先匯出即可保存。

選擇「目前控制」只改變查看及操作的對象，既有飛行、各機航點草稿及歷史不會重設。飛行指令、故障、課程、感測器與雲台各自歸屬指定載具；開始、暫停、速度、風與場景則作用於全隊。外部 PX4／ArduPilot 仍只支援單架四旋翼，不能把多機世界切成多套外部飛控。

## 座標與時間

全隊共用 NED 原點、地形、地理來源、障礙、環境、航門與唯一的 200 Hz 時鐘。起點的高度是離地公尺，地面起始必須為零；任務及 datum 位置指令使用世界基準高度，AGL 指令使用當地離地高度。家點位於世界北／東座標，返航及水平圍欄各依自己的家點判斷；高度圍欄相對家點地高。DEM 必須涵蓋每架的起點與家點。

固定翼只有一條共用跑道，位於 N=0–200 m、E=±15 m，家點不會產生另一條跑道。內建訓練航線相對各機家點及地高；自訂航門維持全世界座標，個別課程放在載具 `setup.training`，不放在場景。

每個時間步先保留全隊控制器、亂數、感測佇列、課程及雲台狀態，再推進所有機體，處理跨機接觸，最後產生共同提交姿態的感測資料。任一架超出 DEM 或出現步進錯誤，所有機體及世界時鐘一併回復，介面暫停全隊。

## 碰撞與感測範圍

跨機接觸使用由機臂／翼展等設定推算的保守球形包絡，檢查一個時間步內兩機相對路徑，可抓到兩端未重疊的高速穿越；它不是機翼、槳葉或機身網格的精確接觸解算。相撞雙方標為墜毀並切除推力，全隊停在同一提交時間步；紀錄包含兩個載具 ID、該步及接觸比例，沒有撞擊後反彈、變形或尾流。

CPU 朝下測距與多層光達會看到其他機的同一保守球形包絡，排除來源機自己；RGB、深度與語意分類則使用實際顯示網格，其他載具為類別 7。兩者共用姿態，但幾何精度不同，不宣稱逐像素／逐射線完全一致。已上鎖或墜毀的機體仍會遮擋。

## 保存及程式控制

飛行紀錄 schema 21、模型 0.15.0，標頭 `world` 保存完整機隊，事件帶 `tick/time` 及必要的 `vehicleId`；每個樣本及感測影格包含相同 tick 的全部載具。CSV 前置 `vehicle_id`、`world_tick`，共 215 欄（含近接資料及三欄電池供電資料），每個時間步每架一列。版本 1–20 不支援，沒有自動轉換；外部 SITL 獨立版本 1 不變。

場景格式為 6；相機資料集為 5，影格記錄 `sourceVehicleId`、`worldTick`。相機的 tick 是來源物理步數：內建為 5 ms，原生 PX4／ArduPilot 分別維持 4／1 ms。格式細節見[程式介接](程式介接.md)、[相機資料](相機資料說明.md)與[場景](場景與賽道.md)。

可從完整 JSON 重新執行全隊事件及 200 Hz 物理，再逐樣本核對飛行與感測結果：

```sh
node tools/replay-world.mjs /absolute/path/to/recording.json
```

效能隨載具數、射線及資料量增加而下降；30 分鐘／約 96 MiB 是全隊共用上限，不是每架各一份。瀏覽器排程及繪圖沒有硬即時保證。所有機型與感測器仍為未經實機校準的教育近似。

## 開源查核

本批先查核 [PX4 v1.17.0 多機世界](https://github.com/PX4/PX4-Autopilot/blob/v1.17.0/docs/en/sim_gazebo_gz/multi_vehicle_simulation.md)的不同 instance／模型身分，以及 [AirSim 多機 API](https://github.com/microsoft/AirSim/blob/1ca93f6f77e4e8a39b2b241c1fe2764da4d7dd41/docs/multi_vehicle.md)的共用 NED 原點與明確機名。另參考 [Flightmare Unity bridge](https://github.com/uzh-rpg/flightmare/blob/d4218aedac18cbe9364a0a0df10ab992c4b65e4f/flightlib/src/bridges/unity_bridge.cpp)的同幀多載具姿態傳送；這不代表它提供本專案的跨機碰撞。僅參考架構，未複製這些專案程式碼。

0.20 批次完成五機混合飛行與瀏覽器重播、真實 DEM 雙機起飛、相機鄰機影像，以及 30 分鐘／96 MiB／越界整批回復測試。獨立重跑的誤差及來源雜湊見[驗證摘要](validation/multi-vehicle-v020.json)。該次 schema 12 歷史紀錄無法匯入現行 schema 21。八機最高光達密度在該次無畫面／Worker／錄製序列化的核心測試約為 0.54 倍即時速度；較低密度不代表所有瀏覽器都能即時運作。
