# 多層光達資料（0.8 版）

多層光達支援 CSV 與 ASCII PCD 匯出。這是單時刻的幾何模擬，並非實機校準或完整市售光達模型。

每一層以 `lidarRays` 條射線環繞 360°（12–180 條），`lidarChannels` 為 1–32 層，預設 8 層。`lidarVerticalMinDeg` 與 `lidarVerticalMaxDeg` 預設為 -30° 與 +10°，範圍均為 -90° 至 +90°，向上為正、向下為負；單層時兩值必須相等，多層時最小角須小於最大角。最多 5,760 條射線。其餘距離範圍、取樣率、雜訊、延遲、丟包及故障沿用感測器設定。

讀數的 `rangesM` 使用層優先順序：同一層先依水平角排列，再排列下一層；`channelCount`、`azimuthCount`、`elevationStartRad`、`elevationStepRad` 描述層數、水平束數與垂直角。讀數保留取樣時間、位置及姿態；輸出的點使用取樣姿態轉換至 NED（北、東、下），座標及距離以公尺表示。無回波以 `null` 表示，不生成對應點。

幾何求交範圍包括共用地形、訓練障礙的軸對齊包圍盒及其他載具的保守包圍球，**不包含完整視覺場景網格**。這是所有射線共用同一姿態的快照，沒有旋轉掃描逐點時間、強度、多回波、反射率、天氣影響、SLAM 或實體校準。內建光達不作為 PX4 SITL 的輸入。

NED 點雲 CSV 僅列有效回波，十欄依序為 `vehicle_id,world_tick,time_s,channel,azimuth_rad,elevation_rad,range_m,north_m,east_m,down_m`，通道從 0 開始。ASCII PCD 0.7 使用 `FIELDS x y z ring range`、`SIZE 8 8 8 2 8`、`TYPE F F F U F`、各欄 `COUNT 1`，`WIDTH` 和 `POINTS` 為有效點數、`HEIGHT` 為 1；`VIEWPOINT` 為取樣 NED 位置及 wxyz 四元數，註解記錄來源載具 ID、世界 tick、掃描時間和 NED 單位。啟動時若尚無取樣姿態，匯出空點檔、使用 PCD 預設 VIEWPOINT，並以註解標示姿態不可用。格式參考 [PCL PCD 0.7 規格](https://pointclouds.org/documentation/tutorials/pcd_file_format.html)。

API 2.3 的 `exportLidarPointCloud(vehicleId, format="pcd")` 接受 `csv` 或 `pcd`，回傳 `{format, frame: "NED", units: "m", sourceVehicleId, worldTick, time, pointCount, text}`。API 僅供內建模式即時使用；UI 可匯出重播中選中載具的掃描。`worldTick` 是匯出當下的共同時鐘，讀數 `time` 是掃描取得時刻，延遲可能使兩者不同。內建紀錄 schema 15、模型 0.10.0；外部 SITL 使用獨立版本 1 紀錄。

設計參考 [AirSim 光達文件](https://github.com/microsoft/AirSim/blob/main/docs/lidar.md)與 [Webots 光達文件](https://github.com/cyberbotics/webots/blob/master/docs/reference/lidar.md)，不代表本專案接入這些模擬器。專案使用 Three.js 0.187.0；Context7 僅索引 r186，相關介面版本須以 [Three.js r187 原始碼](https://github.com/mrdoob/three.js/tree/r187)核對。

先前 0.8 版瀏覽器在倉庫場景以 8 層、每層 72 束掃描，576 條射線中有 380 個有效回波；感測器 JSON 與 schema 6 紀錄最後影格一致，CSV 和 PCD 點座標一致，重播匯出的 PCD 與原檔逐位元組一致。已用 Three.js 0.187 的 PCDLoader 讀取；WebKit 與 Node 重建點座標最大差約 1.776e-15 m。最大 5,760 束達 96 MiB 錄製上限後仍可匯出最後狀態；開關渲染的兩個 Worker 軌跡與感測器結果一致。

[離線效能結果](validation/lidar-v0.8.0.json)：32 × 180 束、20 Hz、50 個障礙盒，1,200 步（6 秒模擬）耗時 333.585 ms，計算速度約為即時 17.986 倍，單次最大採樣更新 8.934 ms。測量不含瀏覽器 GPU，不保證硬即時。

上述歷史驗證資料使用舊 schema，不能匯入現行紀錄；多機版本的瀏覽器驗證仍在進行。
